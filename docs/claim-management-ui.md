# Claim 选择删除与文献重处理

## Claims 页面

1. 使用关系类型、实体类型、结果语义筛选记录。
2. 勾选表格左侧“选择”；换页后，已选 ID 会保留。
3. “选中当前页全部”选中本页；“全选全部筛选结果”覆盖所有匹配页，不受每页 100/250/500 条限制。
4. 页面显示将删除的 claim 数量、文献数量和实际共享影响。点击“删除选中的 N 条 claim”执行。
5. “取消全部选择”清除本次选择。筛选条件之间的选择独立保存，不会把另一个筛选范围的记录混入。

删除只作用于当前知识库所选范围。PDF、文献成员关系和文本分块保留；未选 claim 保留。相应 Fact、参与者/证据关联及失效索引会清理，源记录留存到 claim_history。共享文献会显示实际影响的其他知识库，并要求显式勾选该影响。

预览和提交之间若数据、处理代次或共享范围变化，提交会被拒绝，请刷新后重选。所选文献仍在处理，或有可能重新生成结果的维护任务排队时，也会拒绝删除；先结束或取消这些任务。其他文献的任务不会阻止本次选择删除。

删除不是永久屏蔽规则。以后重新处理对应 PDF，模型仍可能再次抽取相同事实。

## 文献页面

文献表下方增加“重新处理已有文献”：选择一篇或多篇文献，或勾选“全选当前知识库的所有文献”，然后点击重新处理。

- 从 PDF 重新解析并抽取：重新读取原 PDF，重建目录，重新抽取。
- 保留已保存文本，重新抽取：保留人工校正过的源文本，重建目录并重新抽取。

下方“文献处理任务”显示持久保存的任务、排队/处理中/完成/失败/取消状态以及文献结果。它们是维护任务，不会创建新的上传批次；刷新页面后仍可查看。

## 部署

本次后端与前端必须一起更新；worker 更新后会识别数据库中的 cancelled 状态，避免已撤销任务被再次执行。

```bash
cd /home/zhanghaiyang/litkg
sudo docker compose up -d --build api frontend worker_extract worker_parse
```

不需要数据库迁移。当前 SSH 用户没有 Docker 或免密 sudo 权限，需在具备相应权限的终端部署。
